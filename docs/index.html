How it works

One tap between you and your setup

  1. 1

    Tap the tag

    An iPhone automation sees your NFC tag and runs the Send Tap to PC shortcut. The tag holds only a name, like desk-focus-01.

  2. 2

    The phone signs it

    The shortcut hashes the tag, the current time and your pairing secret with SHA-256, and posts the result to your PC over Wi-Fi.

  3. 3

    The PC checks and runs

    NFC Desk checks the request, then runs the script you mapped to that tag from its own library. The request never carries a command.

Built in

What keeps a tap honest

Signed taps

Every request carries a SHA-256 signature over the tag, the time and your secret. Without the secret, nobody on your Wi-Fi can fake one.

No replays

A tap must be within 30 seconds and newer than the last one for that tag, and the agent remembers that across restarts.

Home network only

It listens only on your private LAN addresses, and the firewall rule it offers covers Private networks only.

Cloned tags are useless

A tag holds just a name. Copying it gets an attacker nothing: your phone's secret is what authorises the tap.

No commands on the wire

The request never carries a path or a command. The agent runs only scripts from its own folder, and blocks .., links and shell tricks.

Secret kept by Windows

The pairing secret is encrypted with DPAPI for your Windows account, never stored in plain text.

Says no quietly

Every failure gets the same 403 denied. The reason goes in your log, not to whoever is asking.

Rate limited

Ten requests a second per address, a 1 KB body limit, and every attempt logged with time, address, tag and result.

No admin

Runs with your normal rights. The only elevation is one optional prompt to add the firewall rule.

Protocol

Small enough to read

One endpoint, three fields. Build your own sender if you like: anything that signs the same way works.

Request

# POST http://<pc-ip>:8765/tap
{
  "tag": "desk-focus-01",
  "ts":  1763441000,
  "sig": "def92307…10c54"
}

# sig = lowercase hex of
SHA256( tag + "|" + ts + "|" + secret )

Response

# passed every check
200 {"status":"ok"}

# failed any check, no detail
403 {"status":"denied"}

# tag: ^[a-z0-9-]{1,64}$
# ts:  whole Unix seconds, number or string

FAQ

Questions

Is it free?

Yes. NFC Desk and the iPhone shortcut are free. Sponsors keep it that way.

Does it go through the internet or a cloud service?

No. The phone talks straight to your PC over your home Wi-Fi. The agent only accepts requests from private network addresses, and there's no account or telemetry.

What do I need?

A Windows 10 or 11 PC, an iPhone that can run NFC automations in Shortcuts, and any blank NFC tags. The phone and the PC must be on the same home network.

Someone copied my NFC tag. Can they trigger my PC?

No. The tag only holds a name. A tap counts only when it's signed with the secret stored on your phone, so a copied tag tapped with another phone is refused.

Could someone on my Wi-Fi replay a tap they saw?

No. Each tap includes the time, must arrive within 30 seconds, and must be newer than the last accepted tap for that tag. A captured request is refused the second time.

Does it need admin rights?

No. It runs as you. The first time it starts, it offers to add a Windows Firewall rule for Private networks; that one step asks for permission, and you can skip it and add the rule yourself.

My iPhone says the PC didn't respond.

Check that NFC Desk is running, that the phone is on the same Wi-Fi, and that the network is set to Private in Windows (the tray tooltip warns you when it isn't). If your PC's address changed, copy the new URL from Pair Phone into the shortcut, or reserve the address in your router.

Can I test it without a phone?

Yes. tools/send-test-tap.ps1 sends signed taps from PowerShell, including deliberately bad ones (wrong signature, old timestamp, replays) so you can watch the log refuse them.

How do I uninstall it?

Turn off Start with Windows, quit from the tray, delete the exe and the %AppData%\NFCDesk folder, and remove the "NFC Desk Agent" firewall rule if you added it.

Can I see the code?

Yes, it's public on GitHub, along with SECURITY.md, which explains the threat model and what each check stops.
